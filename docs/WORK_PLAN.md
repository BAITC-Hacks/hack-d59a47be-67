# Рабочий план Алихана

Ниже сохранён план инфраструктурного этапа. На 2026-09-23 пункты 1–5 реализованы и проверены: предметные endpoints больше не возвращают 501, первичное ТЗ сверено, импорт проверен на ките. HR summary пока содержит базовые counts; расширенная аналитика остаётся следующим срезом. Передача — docs/HANDOFF.md; доказательства — docs/VERIFICATION.md. Подключение AI Олега и проверка Docker остаются следующими шагами.

1. Каркас, постоянная SQLite, миграции, health/version, demo-auth, RBAC и CSRF — текущий реализованный этап.
2. Единый контракт v1 и синтетические примеры — передать Батыру и Олегу; текущие предметные endpoints возвращают 501.
3. После сверки первичного ТЗ реализовать валидатор и транзакционный импорт четырех исходных файлов с dry_run. Учесть skills snapshot на last_review_date и историю после ревью; не начислять эффекты истории дважды. Добавить версии данных/состояния.
4. Реализовать каталог, профили/цели/разрывы, HR-агрегаты и пагинацию, сохраняя контроль доступа. Требования цели и арифметика берутся из исходных `role_profiles` и `develops_skills`, не из модели.
5. Отдельно реализовать кандидатов, preview без записи и идемпотентные completions/явную demo_simulation. Mandatory исключать из рекомендаций; завершенные не повторять кроме EV_036. Проверить gain/max_level, даты и ограничения из данных.
6. Подключить реализацию Олега через существующий adapter и те же Pydantic-классы. Не создавать собственный LLM-клиент; модель выбирает event_id и объясняет с evidence_id, backend выполняет остальные операции.
7. Проверить Docker build/Compose и постоянство volume на машине с Docker. HTTPS-staging и публичный деплой требуют отдельного фактического запуска; сейчас не заявлены.

Алихан: backend/данные/API/права/интеграция/деплой. Олег: `backend/app/ai/` и собственные тесты. Батыр: `frontend/`. Preview — функция команды, не подтвержденное требование организаторов. Push/merge только по явному разрешению пользователя.
