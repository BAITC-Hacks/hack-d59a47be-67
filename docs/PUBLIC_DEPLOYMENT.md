# Публичная демонстрация Career Quest

Подготовлен один Docker-сервис: собранный React-интерфейс и FastAPI работают на одном адресе. [render.yaml](../render.yaml) явно выбирает **Free**, без платного диска, Postgres и дополнительных сервисов. Репозиторий может оставаться приватным; публичным становится адрес приложения. Само наличие конфигурации не означает, что платформа уже опубликована.

В публичном режиме каждый посетитель получает отдельную временную SQLite-базу с вымышленными примерами команды. Можно пройти сценарий сотрудника и посмотреть HR, не меняя данные других посетителей. Сервер рассчитывает навыки, проверяет права, сохраняет результат в пределах этой демонстрации. Исходный кит организаторов, личные профили, локальные `.env` и ключи в Docker-образ не входят.

## Бесплатный Render: подтверждённые условия

Сверено с официальной документацией **23 сентября 2026 года**:

- После 15 минут без входящего трафика сервис засыпает; следующий запуск занимает примерно минуту.
- Файлы и SQLite теряются при остановке, перезапуске или новом развёртывании. Бесплатный web-сервис не поддерживает постоянный диск.
- На рабочее пространство выделяется 750 бесплатных часов в месяц; также действуют лимиты трафика и сборок. При добавленной оплате превышения некоторых квот могут оплачиваться отдельно.

Источники: [Render Free](https://render.com/docs/free), [поля Blueprint и выбор плана](https://render.com/docs/blueprint-spec). Это конфигурация демонстрации, а не постоянного хранилища результатов сотрудников. Холодный запуск не соответствует требованию отклика до двух секунд; измерения прогретого приложения нужно фиксировать отдельно. Автоматические запросы для обхода сна не настроены.

## Опубликовать из репозитория

1. Войти в [Render Dashboard](https://dashboard.render.com/) под учётной записью команды. Подключить GitHub и разрешить Render доступ именно к `BAITC-Hacks/hack-d59a47be-67`. Для приватного репозитория организации может потребоваться разрешение её владельца на GitHub App.
2. Создать **New → Blueprint**, выбрать этот репозиторий, ветку **`feat/product-ready`** и файл **`render.yaml`** в корне. Инструкция Render: [создание Blueprint](https://render.com/docs/infrastructure-as-code).
3. В предварительном списке проверить: один web-сервис `career-quest-public`, Docker, план **Free**, регион Frankfurt; нет дисков и баз данных. Затем создать сервис. Настройки запуска берутся из Dockerfile, дополнительная команда сборки не нужна.
4. Дождаться успешной сборки и readiness. Открыть HTTPS-адрес, который Render покажет на странице сервиса. Адрес вида `https://<выданное-имя>.onrender.com` здесь является шаблоном, а не уже работающей ссылкой.
5. Пройти проверки ниже и передать фактический адрес жюри. Автоматическое развёртывание отключено: обновления публикуются через **Manual Deploy** после проверок нужного коммита.

Render передаёт `RENDER_EXTERNAL_URL`; сервер добавляет этот точный origin для cookie/CSRF. Для собственного домена задайте `PUBLIC_BASE_URL=https://ваш-домен` без завершающего `/`. Wildcard-origin не нужен. Используются `APP_ENV=staging`, Secure/HttpOnly cookie и один процесс приложения. Источник системных переменных: [Render environment variables](https://render.com/docs/environment-variables).

## AI включается отдельно

По умолчанию `AI_ENABLED=false`: сайт запускается без ключа и показывает `not_configured`. Подготовленные ответы браузерного демо не подтверждают работу модели. Серверный каталог, профиль, завершение, импорт и HR доступны независимо от AI.

Чтобы проверять настоящий подбор, в **Environment** сервиса добавьте `OPENAI_API_KEY` как секрет и только затем установите `AI_ENABLED=true`. `OPENAI_MODEL` и `AI_TIMEOUT_SECONDS` уже заданы в Blueprint; модель должна быть доступна выбранному проекту провайдера. Не вставляйте ключ в `render.yaml`, Docker build arguments, frontend или Git. Стоимость вызовов модели не входит в бесплатный хостинг. После повторной синхронизации Blueprint проверьте `AI_ENABLED`: значение из файла по умолчанию снова выключает AI.

При включённом AI публичные вызовы ограничены сервером, но это не заменяет лимит расходов в проекте провайдера. Успешный `/api/health` с `configured` ещё не доказывает успешный ответ модели: нужна фактическая рекомендация и её объяснение на новом серверном состоянии.

## Проверка опубликованного приложения

1. Открыть страницу в обычном и приватном окне браузера. Начать серверную демонстрацию в каждом; данные и изменения должны быть независимы.
2. В роли сотрудника: профиль → рекомендации → раскрытое объяснение → предварительный результат → завершение. Проверить обновлённые навыки и прогресс, историю и сохранение после перезагрузки страницы в той же сессии. При выключенном AI проверить тот же путь через каталог и честное `not_configured`.
3. Перейти в HR своего пространства: разрывы навыков, период участия, причины внимания; после завершения обновить срез. Импортировать только вымышленные проверочные JSON/CSV через предварительную проверку и подтверждение.
4. Убедиться, что сотрудник получает 403 при запросе чужого профиля и HR API. Проверить неверный импорт и повтор завершения с тем же Idempotency-Key: повторного начисления нет.
5. На 390 px раскрыть длинное объяснение: горизонтальной прокрутки всей страницы быть не должно. Проверить `/api/health/ready` и записать SHA, браузер, дату, задержки и результат сценария.

Рабочее пространство действует ограниченное время; его завершение или перезапуск бесплатного хоста требует новой демонстрации. Вымышленные начальные данные восстанавливаются автоматически. Не используйте эту площадку для постоянных данных или персональных сведений. Квота публичного режима может вернуть 429; это причина повторить проверку позже, а не замаскированный успешный ответ.

## Тот же публичный режим локально

Нужен Docker с Compose. Из корня репозитория:

```sh
docker compose -f compose.public.yaml up --build
```

Открыть [http://localhost:8080](http://localhost:8080). В этой конфигурации внешний порт привязан к loopback, HTTPS не используется, поэтому Secure-cookie выключена только локально. Compose не монтирует исходный кит и постоянный volume. Чтобы остановить эту демонстрацию:

```sh
docker compose -f compose.public.yaml down
```

`compose.public.yaml` — самостоятельная конфигурация; не объединяйте её с `compose.yaml`. Обычный приватный запуск остаётся доступен через `docker compose -f compose.yaml up --build`: там публичный режим выключен и база сохраняется в отдельном named volume; данные и аккаунты создаются по [HANDOFF](HANDOFF.md). Не включайте публичный режим поверх существующей рабочей базы.

## Статус проверки конфигурации

Dockerfile собирает frontend через Node 24 и pnpm 11.25.0 с frozen lock-файлом, затем копирует только `dist` в Python 3.12.14 runtime. Процесс работает как UID/GID 10001, слушает переменную `PORT`, статические файлы находятся в `/app/frontend/dist`, SQLite — в `/data`. `.dockerignore` допускает только исходники сборки и runtime; `node_modules`, исходный кит, локальные БД и секреты исключены.

Для машинной проверки на хосте с Docker предусмотрено:

```sh
python scripts/check_container.py --require-ai
```

Проверка использует отдельный Compose project и синтетические данные; проверяет собранную страницу и JS-ресурс, права, cookie, SQLite и сохранение результата при пересоздании приватного контейнера. Она не делает платных AI-вызовов и не подтверждает публичный деплой. Если Docker отсутствует, возвращаются **NOT RUN** и код 2. На машине подготовки Docker отсутствует: сборка нового fullstack-образа и постоянный адрес Render пока не подтверждены. Временная публичная ссылка проверена отдельно ниже.


## Временная ссылка и фактическая проверка 23.09.2026

Запущена временная публичная копия через Cloudflare Quick Tunnel. Она обслуживает только отдельный публичный режим с собственными вымышленными данными, не частный сервер команды. Ссылка на действующий сеанс находится в корневом README; после остановки компьютера/туннеля она перестаёт работать. Это бесплатный способ показать прототип, но не замена Render или постоянному серверу. Условия: [Cloudflare Quick Tunnels](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/do-more-with-tunnels/trycloudflare/).

Через внешний HTTPS выполнены 19 запросов: сессии сотрудника/HR с Secure+HttpOnly cookie, запрет HR сотруднику, честный not_configured без AI-вызова, preview, completion и точный idempotent replay, раздельные данные посетителей, скачивание вымышленных JSON/CSV и preview/commit трёх новых профилей (3 → 6), неверный Origin и logout. Всё PASS. Прогресс сотрудника 56,25% → 62,5%. Наблюдаемая медиана HTTP 1101,90 мс, максимум 2158,23 мс; это одиночная проверка туннеля, не SLA UI/AI и не нагрузочный тест. Браузер открыл публичный HR со всей аналитикой. Полный live AI и Docker/Render остаются отдельно непроверенными.
