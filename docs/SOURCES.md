## Семантика из README

- Шкала навыков — 0–5; отсутствующий навык сотрудника имеет уровень 0. Уровни в профиле отражают последнюю оценку. Завершённые после `last_review_date` мероприятия ещё не учтены; нельзя безусловно повторно начислять всю историю.
- Грейды в порядке роста: `Junior`, `Middle`, `Senior`, `Lead`. Требования находятся в `role_profiles`; `critical_skills` должны соответствовать требованиям целевого грейда.
- `career_goal` имеет вид `{target_role, target_grade}` либо `null`.
- `develops_skills[]` содержит `{skill_id, gain, max_level}`. Прирост ограничен `max_level`; мероприятие не должно уменьшать уже имеющийся уровень.
- `mandatory=true` исключает мероприятие из рекомендаций. Обязательные мероприятия сохраняются в истории.
- Завершённое мероприятие не повторяется, кроме регулярного клуба `EV_036`.
- `self_paced` доступно без дат сессий; пустой `upcoming_sessions` для этого формата корректен.
- Статусы истории: `completed`, `in_progress`, `dropped`, `no_show`, `declined`, `overdue`. `assigned_by`: `self`, `manager`, `hr`.
- Для `completed` `completion_pct=100`; `in_progress` и `overdue` — 0–95; `dropped` — 5–95; `no_show` и `declined` — 0. `no_show` применим только к мероприятиям по расписанию.
- `due_date` заполнен только для обязательных мероприятий. `score` может отсутствовать; применим к курсам, сертификациям и комплаенсу. `feedback_rating` необязателен.
- Для оценки предусмотрены дополнительные профили и история в том же формате. Наличие описанной схемы не означает, что импорт уже реализован: endpoint импорта остаётся planned до разработки и проверки полного преобразования.
