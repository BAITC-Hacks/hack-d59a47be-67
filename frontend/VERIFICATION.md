# Проверки Frontend / UX

Проверено локально 2026-09-23 на Windows, Node.js 24.19.0, Python 3.12.14. Основа — backend из `codex/architecture-foundation` (`e3dfc7e`). Использованы собственные вымышленные данные; исходный кит и реальные профили не публиковались.

## Автоматические проверки

- `pnpm test`: 52 теста в 6 файлах. API-клиент (11), синтетические состояния (7), маршруты/сессии приложения (8), сценарии сотрудника (13), чтение файлов и импорт (13).
- Проверяются CSRF/cookie, отсутствие автоматического перехода в демо, ограничения роли, запоздалые ответы при смене пользователя, устаревшие рекомендации после мутации, сохранение версии/тела/idempotency key при повторе завершения после сетевой ошибки и перезагрузки, импорт с preview token, двойные клики, конфликт и потеря ответа.
- `pnpm build`: TypeScript и production bundle успешно собраны.
- `pnpm format:check`: PASS. `pnpm generate:api` не меняет SHA-256 уже сгенерированного `src/api/schema.ts`.
- `.venv/Scripts/python.exe frontend/scripts/test-live.py`: проверки настоящего HTTP API на временной SQLite-базе. Вход/сессия/CSRF/права; профиль/каталог/честный `not_configured`; preview/завершение/replay/409; stale latest; успешный и ошибочный импорт; повторный запуск backend с сохранением профиля, сессии, импорта и идемпотентности.
- Ruff check и format для двух Python-скриптов: PASS. Runner проверен на отдельных портах `8001/5174`: backend readiness, UI и proxy 200, отказ на занятых портах до seed, остановка собственных процессов при Ctrl+C и сбое backend. Существующий сервер не затронут.

## Проверка интерфейса в браузере

- Демо: вход без пароля, подбор трёх подготовленных рекомендаций, объяснения, предварительный результат, подтверждение завершения. Прогресс 72,7% → 86,4%; предыдущая подборка помечается устаревшей; состояние сохраняется после перезагрузки. Сброс возвращает начальный профиль.
- Настоящий API с отдельными синтетическими учётками: вход сотрудника, профиль/каталог, сообщение об отключённом AI, preview и завершение курса. Серверный прогресс 56,3% → 62,5%; обновлённая история сохраняется после перезагрузки.
- HR: вход, серверная сводка, список сотрудников. Некорректный JSON показывает файл и путь ошибочного поля. Корректные JSON+CSV проходят preview с одним новым профилем и одной записью истории; после подтверждения сотрудник появляется в списке, счётчик растёт с 3 до 4.
- Адаптивность: кабинет сотрудника, HR и импорт на ширине 390 px, кабинет и навыки на 320 px; проверены мобильное меню и диалог цели. Устранено переполнение страницы таблицей HR; закрытая панель навигации скрыта от клавиатуры. Диалоги используют нативный `dialog`, есть подписи полей и переход к основному содержимому.

Проверка браузером выполнена вручную через автоматизированные действия и осмотр экранов, а не отдельным воспроизводимым e2e-suite. Полный аудит WCAG, проверка всех браузеров/устройств и нагрузочные измерения не проводились.

## Редизайн и критерии отбора — 2026-09-23

- Обновлены вход, навигация, цель/прогресс, рекомендации, HR и импорт в зелёной/золотистой палитре с собственным SVG-орнаментом. Рекомендации расположены строками с объяснением рядом; круговой индикатор заменён нативным `progress`, доступным скринридеру. SVG не требует внешней сети, не принимает пользовательскую разметку и не содержит исполняемого кода.
- После изменений: 52 теста в 6 файлах PASS, TypeScript/build и Prettier PASS. Тест конфликта версии теперь проверяет точное серверное значение доступного progressbar вместо округлённой текстовой цифры. Vitest ограничен тестами `src/`, чтобы локальные копии для воспроизводимости не удваивали прогон.
- Установка `pnpm install --frozen-lockfile` в отдельной копии frontend без `node_modules` и сборка прошли. Использован локальный pnpm store на той же Windows-машине; это проверка отсутствия зависимости от прежнего `node_modules`, а не подтверждение новой ОС, контейнера или недоступного registry.
- В браузере проверены обновлённые вход, профиль, рекомендации, диалог, HR и импорт. Демо-завершение сохраняет рост 72,7% → 86,4% и делает подборку устаревшей. На ширинах 390 и 320 px содержимое не расширяет страницу горизонтально; диалог прокручивается на маленькой высоте.
- [Матрица технического отбора](JURY.md) использует предоставленные веса 20/25/20/20/15. Полная AI-интеграция, HR-агрегаты и production остаются пробелами; оформление и браузерные fixtures не засчитываются вместо них.

## Длинное объяснение на мобильном экране и API — 2026-09-23

- Воспроизведён дефект из отчёта Олега: при `innerWidth=390` открытое объяснение увеличивает `documentElement.scrollWidth` до 841 px. Использован настоящий `EmployeeWorkspace` с синтетическим текстом `contracts/examples/ai_enriched_result.synthetic.json` из `codex/backend-ai-handoff` (`a3696ba`) в отдельной локальной QA-странице. Это проверка отображения согласованного ответа, без обращения к модели и без подмены рабочего API.
- Причина — длинные фрагменты JSON/идентификаторы без пробелов. `.why-details` получил `min-width: 0`, текст — `overflow-wrap: anywhere`. Текст не обрезается, горизонтальное переполнение не скрывается стилем страницы. После исправления на 390 px ширина документа равна доступным 375 px (15 px занимает полоса прокрутки); на 320 px — 305 px. Проверены раскрытие нескольких карточек и desktop 1440 px.
- Через обычную форму на настоящем локальном API повторно проверены вход сотрудника, профиль и запрос рекомендаций. AI остаётся `not_configured/none`; UI корректно сообщает об этом. Затем из каталога выполнены preview и обычное завершение синтетической активности «Надёжные сервисы на Python»: навык 3 → 4, серверный прогресс 62.5% → 68.75% (UI 62,5% → 68,8%). После перезагрузки сохранены прогресс и запись «Завершено» в истории. Рабочая учебная база не сбрасывалась.
- Повторные проверки: 52 frontend-теста, HTTP smoke на отдельной временной БД, TypeScript/build и Prettier — PASS. Unit-тесты используют тестовые клиенты, HTTP smoke — настоящий backend с отключённым AI. Весь путь через живую AI-рекомендацию на этой машине не подтверждён.
- В актуальной AI-ветке (`f10006a`) есть отдельный отчёт коллеги `backend/app/ai/INTEGRATION_REPORT.md` о совместной live-проверке. Это результат его окружения, а не новый прогон здесь. Для нашей проверки всё ещё нужны объединённые AI/backend-handoff изменения, локальная конфигурация модели и обычный `pnpm start`; `start:demo` выключает AI.
