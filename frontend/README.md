# Career Quest — Frontend / UX

Рабочее пространство сотрудника и HR на React, TypeScript и Vite. Сотрудник видит цель, требования к навыкам, объяснение следующего шага и изменение прогресса после завершения. HR открывает профили и загружает профили вместе с историей через серверную проверку и подтверждение.

## Быстро посмотреть интерфейс

Нужны Node.js 22.12+ и pnpm 11.25.0. Из корня репозитория:

```bash
cd frontend
pnpm install --frozen-lockfile
pnpm dev
```

Откройте `http://127.0.0.1:5173` и нажмите **«Посмотреть демо»**. Backend для этого режима не нужен. Демо явно помечено, использует только вымышленные данные и заранее подготовленные ответы; работа AI здесь не заявляется. Можно пройти рекомендацию, посмотреть результат, историю, кабинет HR и сбросить демо. Пользовательские файлы этот режим не принимает.

## Приложение с настоящим API на синтетических данных

Установите Python 3.12, создайте `.venv` в корне и установите серверные зависимости. В PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.lock
cd frontend
pnpm install --frozen-lockfile
pnpm start:demo
```

В Linux/macOS:

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.lock
cd frontend
pnpm install --frozen-lockfile
pnpm start:demo
```

Команда запускает существующий backend на `127.0.0.1:8000` и UI на `127.0.0.1:5173`. Для входа через обычную форму возьмите локальные логин и случайный пароль сотрудника или HR из `frontend/.local-demo.json`. Не публикуйте этот файл. Отдельная база `frontend/.qa/demo.sqlite3` и учётные записи создаются только один раз; последующие запуски сохраняют изменения. Чужая база не перезаписывается. Локальные данные исключены из Git.

В этом режиме профили, завершения, история и импорт работают через настоящий API и SQLite. AI отключён: экран сообщает, что подбор ещё не подключён; проверять рост можно из каталога. Кнопка «Посмотреть демо» по-прежнему открывает отдельный браузерный сценарий с подготовленными рекомендациями.

`Ctrl+C` останавливает процессы этого запуска. Занятые порты не освобождаются принудительно. При необходимости задайте `CQ_API_PORT`, `CQ_UI_PORT`, `CQ_PYTHON` до запуска.

## Подключение командного backend

Подготовка базы, импорт исходного кита, учётные записи и настройки сервера описаны в [HANDOFF](../docs/HANDOFF.md). После подготовки можно запустить оба процесса командой `pnpm start` из `frontend/`: она использует существующий `DATABASE_PATH` и корневой `.env`, не создаёт демонстрационные данные. Корневая `.venv` должна содержать серверные зависимости.

Если backend уже запущен, используйте только `pnpm dev`. По умолчанию Vite проксирует `/api` на `http://127.0.0.1:8000`; другой адрес задаётся через `API_PROXY_TARGET`. Backend должен разрешать точный origin UI в `ALLOWED_ORIGINS`. Вызовы идут через один origin с cookie и CSRF; секреты и адрес модели в UI не передаются.

Для локальной проверки сборки: `pnpm build`, затем `pnpm preview` (`127.0.0.1:4173`). При работе с API этот origin также нужно разрешить на сервере. Vite dev/preview — локальные инструменты; публичное развёртывание остаётся задачей интегратора.

## Пользовательские сценарии

- **Сотрудник:** цель и прогресс → навыки → рекомендации с основаниями → предварительный результат активности → подтверждение завершения → новые серверные значения и история. Процент означает соответствие навыков требованиям, а не обещание повышения.
- **Каталог:** поиск, форматы и предварительная проверка сервером. Обычное завершение требует подтверждения фактического выполнения; учебная симуляция отдельно помечена.
- **HR:** серверная сводка и список с пагинацией → профиль сотрудника. Поиск явно ограничен загруженной страницей.
- **Импорт:** `employees.json` и/или `activity_history.csv` в UTF-8 → проверка без записи → количества и предупреждения → явное подтверждение. Ошибки, изменения после проверки и потеря ответа имеют отдельные действия восстановления. Формат — в [API v1](../contracts/API.md).
- **Необычные состояния:** ожидание, нет цели/кандидатов, цель достигнута, недостаточно оснований, AI не настроен/недоступен, fallback, устаревшие рекомендации, конфликт версии, завершившаяся сессия. Ошибка API никогда автоматически не подменяется демо.

## Контракты и границы

Источник схем — [Python-модели](../backend/app/contracts.py) и экспорт [OpenAPI](../contracts/openapi.json). `pnpm generate:api` воспроизводимо создаёт `src/api/schema.ts`. Ручной второй набор HTTP-схем не поддерживается. Согласованные правила: [API v1](../contracts/API.md), [AI v1](../contracts/AI_CONTRACT.md), [план команды](../docs/team-plan.md).

Backend рассчитывает навыки, доступность, прогресс и проверяет права. AI выбирает мероприятия. UI отображает ответы и отправляет команды; синтетический адаптер возвращает подготовленные состояния без реализации серверной арифметики. Повтор завершения после сетевой ошибки сохраняет тот же `Idempotency-Key`, тело и версию состояния, в том числе после перезагрузки вкладки.

```text
src/api/                 HTTP client, generated types, explicit demo adapter
src/features/employee/   profile, skills, recommendations, catalog, history
src/features/hr/         summary and employee list
src/features/import/     file validation, preview and commit
src/components/          shared accessible UI
scripts/                 isolated seed, live HTTP smoke, local process runner
```

## Проверки и оставшаяся интеграция

```bash
pnpm test
pnpm build
pnpm format:check
```

Дополнительно из корня: `.venv/bin/python frontend/scripts/test-live.py` (в Windows — `.\.venv\Scripts\python.exe`). Проверка сама создаёт временную синтетическую базу, запускает реальный HTTP-сервер и проверяет сессии, права, CSRF, завершения, повторы, конфликт версии, импорт и сохранение после перезапуска. Рабочую базу она не использует.

Результаты фактически выполненных проверок — [VERIFICATION](VERIFICATION.md). Для полной демонстрации командного продукта ещё нужны работающий AI-модуль Олега, серверная агрегированная аналитика пробелов/участия Алихана и проверенное развёртывание. UI не выдаёт имеющиеся счётчики HR за эту аналитику. Live AI, Docker, production, нагрузочные SLA и полный командный acceptance этим изменением не подтверждены.

На момент передачи AI подготовлен отдельно в [draft PR #3](https://github.com/BAITC-Hacks/hack-d59a47be-67/pull/3), но ещё не входит в основу. Его HTTP-контракт совместим с UI. После командного review и объединения интегратору нужно настроить AI по документации этой ветки, дополнить серверные facts для evaluation-сценариев и пройти общий сценарий. Для этого используется обычный `pnpm start`: `start:demo` намеренно выключает AI.
