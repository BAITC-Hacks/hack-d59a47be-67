# Career Quest — Frontend / UX

Рабочее пространство сотрудника и HR на React, TypeScript и Vite. Сотрудник видит цель, требования к навыкам, объяснение следующего шага и изменение прогресса после завершения. HR видит разрывы навыков, факты участия и основания для поддержки, открывает профили и загружает новые данные через серверную проверку и подтверждение.

Визуальное направление — Halyk: зелёная навигация, тёплая светлая основа, золотистые детали и локальный SVG-орнамент по мотивам казахского узора. Основные действия, серверные права и контракты сохранены. Прогресс отображается доступным `progress` с точным серверным значением; пояснение рядом отделяет готовность навыков от обещания повышения. [Проверка по критериям отбора 20/25/20/20/15](JURY.md).

## Публичная проверка через настоящий сервер

При `PUBLIC_DEMO_MODE=true` на странице входа доступны **«Кабинет сотрудника»** и **«Кабинет HR»** без общего пароля. Каждый посетитель получает отдельную временную SQLite-копию собственных вымышленных данных проекта. Оба кабинета в одном браузере используют одну копию; другие посетители её не меняют. Навыки, прогресс, права, аналитика и импорт обрабатываются настоящим API. Подготовленные браузерные рекомендации здесь не используются.

В кабинете HR есть ссылки **«Пример профилей JSON»** и **«Пример истории CSV»**. Скачайте оба файла, откройте «Импорт данных», выберите файлы, выполните проверку и подтвердите загрузку. В исходной новой копии после импорта станет шесть сотрудников вместо трёх. Файлы содержат только собственные вымышленные профили; автоматического импорта при скачивании нет.

AI-модуль и обогащённый серверный контекст уже входят в общую версию. Для настоящих рекомендаций на сервере нужны разрешённый ключ и `AI_ENABLED=true`. Без них интерфейс честно показывает недоступный подбор, а каталог и остальные операции продолжают работать. Публичный режим постоянно обозначает вымышленные данные и временное хранение; он не предназначен для персональных данных или постоянного учёта.

Подготовлена [инструкция бесплатного размещения](../docs/PUBLIC_DEPLOYMENT.md) с Render Blueprint. Постоянный публичный адрес ещё не подтверждён: требуется вход владельца в хостинг и фактическое развёртывание. Бесплатный хостинг не оплачивает запросы модели; сон сервиса и потеря временной базы описаны в инструкции.

Тот же режим предусмотрен локально через Docker с Compose, из корня:

```bash
docker compose -f compose.public.yaml up --build
```

Открыть [http://localhost:8080](http://localhost:8080). На машине подготовки Docker отсутствует, поэтому сборка и запуск этого образа пока не проверены. Проверенный локальный путь без Docker описан ниже.

## Отдельные готовые примеры интерфейса

Нужны Node.js 22.12+ и pnpm 11.25.0. Из корня репозитория:

```bash
cd frontend
pnpm install --frozen-lockfile
pnpm dev
```

Откройте `http://127.0.0.1:5173` и нажмите **«Посмотреть демо»**. Backend для этого режима не нужен. Демо явно помечено, использует только вымышленные данные и заранее подготовленные ответы; работа AI здесь не заявляется. Можно пройти рекомендацию, посмотреть результат, историю, список HR и сбросить демо. Импорт пользовательских файлов и агрегированная HR-аналитика в этом адаптере недоступны: для них нужен настоящий сервер. На публичном сервере вместо этой кнопки показаны два рабочих кабинета.

## Приложение с настоящим API на синтетических данных

Установите Python 3.12, создайте `.venv` в корне и установите серверные зависимости. В PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.lock
cd frontend
pnpm install --frozen-lockfile
pnpm start:demo
```

В Linux/macOS:

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.lock
cd frontend
pnpm install --frozen-lockfile
pnpm start:demo
```

Команда запускает существующий backend на `127.0.0.1:8000` и UI на `127.0.0.1:5173`. Для входа через обычную форму возьмите локальные логин и случайный пароль сотрудника или HR из `frontend/.local-demo.json`. Не публикуйте этот файл. Отдельная база `frontend/.qa/demo.sqlite3` и учётные записи создаются только один раз; последующие запуски сохраняют изменения. Чужая база не перезаписывается. Локальные данные исключены из Git.

В этом режиме профили, завершения, история, HR-аналитика и импорт работают через настоящий API и SQLite. AI намеренно отключён командой `start:demo`: рост можно проверить из каталога. Кнопка «Посмотреть демо» открывает отдельный браузерный сценарий с подготовленными рекомендациями; он не заменяет эти API-операции.

`Ctrl+C` останавливает процессы этого запуска. Занятые порты не освобождаются принудительно. При необходимости задайте `CQ_API_PORT`, `CQ_UI_PORT`, `CQ_PYTHON` до запуска.

## Подключение командного backend

Подготовка базы, импорт исходного кита, учётные записи и настройки сервера описаны в [HANDOFF](../docs/HANDOFF.md). После подготовки можно запустить оба процесса командой `pnpm start` из `frontend/`: она использует существующий `DATABASE_PATH` и корневой `.env`, не создаёт демонстрационные данные. Корневая `.venv` должна содержать серверные зависимости.

Если backend уже запущен, используйте только `pnpm dev`. По умолчанию Vite проксирует `/api` на `http://127.0.0.1:8000`; другой адрес задаётся через `API_PROXY_TARGET`. Backend должен разрешать точный origin UI в `ALLOWED_ORIGINS`. Вызовы идут через один origin с cookie и CSRF; секреты и адрес модели в UI не передаются.

Для локальной проверки сборки: `pnpm build`, затем `pnpm preview` (`127.0.0.1:4173`). При работе с API этот origin также нужно разрешить на сервере. Vite dev/preview — локальные инструменты; публичный образ раздаёт готовый `dist` через FastAPI на одном адресе по [инструкции развёртывания](../docs/PUBLIC_DEPLOYMENT.md).

Код AI и серверные facts объединены; отдельно сливать прежние ветки для запуска больше не требуется. Настройка модели — в [AI README](../backend/app/ai/README.md), ключ добавляется только в локальную конфигурацию сервера или секрет хостинга. Обычный `pnpm start` читает корневой `.env`; `pnpm start:demo` принудительно выключает AI. Наличие модуля и статус `configured` сами по себе не доказывают успешного обращения к провайдеру.

## Пользовательские сценарии

- **Сотрудник:** цель и прогресс → навыки → рекомендации с основаниями → предварительный результат активности → подтверждение завершения → новые серверные значения и история. Процент означает соответствие навыков требованиям, а не обещание повышения.
- **Каталог:** поиск, форматы и предварительная проверка сервером. Обычное завершение требует подтверждения фактического выполнения; учебная симуляция отдельно помечена.
- **HR:** прежняя сводка и список с пагинацией дополнены серверной аналитикой за 30/90/180 дней. Видны частота разрывов до цели, критичные навыки, конкретные основания поддержки и участие с полным набором статусов. Подписаны дата среза, знаменатели, приблизительные исторические даты и исключённые симуляции. Отсутствие истории обозначается отсутствием данных, а не оценкой вовлечённости; рейтинга сотрудников нет. Поиск списка явно ограничен загруженной страницей.
- **Импорт:** `employees.json` и/или `activity_history.csv` в UTF-8 → проверка без записи → количества и предупреждения → явное подтверждение. Ошибки, изменения после проверки и потеря ответа имеют отдельные действия восстановления. Формат — в [API v1](../contracts/API.md).
- **Необычные состояния:** ожидание, нет цели/кандидатов, AI не настроен/недоступен, устаревшие рекомендации, конфликт версии, завершившаяся сессия. Ошибка API никогда автоматически не подменяется демо. Отдельные состояния fallback и insufficient_evidence не входят в действующий HTTP-контракт и реализованными не заявляются.

## Контракты и границы

Источник схем — [Python-модели](../backend/app/contracts.py) и экспорт [OpenAPI](../contracts/openapi.json). `pnpm generate:api` воспроизводимо создаёт `src/api/schema.ts`. Ручной второй набор HTTP-схем не поддерживается. Согласованные правила: [API v1](../contracts/API.md), [AI v1](../contracts/AI_CONTRACT.md), [план команды](../docs/team-plan.md).

Backend рассчитывает навыки, доступность, прогресс и проверяет права. AI выбирает мероприятия. UI отображает ответы и отправляет команды; синтетический адаптер возвращает подготовленные состояния без реализации серверной арифметики. Повтор завершения после сетевой ошибки сохраняет тот же `Idempotency-Key`, тело и версию состояния, в том числе после перезагрузки вкладки.

```text
src/api/                 HTTP client, generated types, explicit demo adapter
src/features/employee/   profile, skills, recommendations, catalog, history
src/features/hr/         server analytics, summary and employee list
src/features/import/     file validation, preview and commit
src/components/          shared accessible UI and public server entry
scripts/                 isolated seed, live HTTP smoke, local process runner
```

## Проверки и текущие ограничения

```bash
pnpm test
pnpm build
pnpm format:check
```

Дополнительно из корня: `.venv/bin/python frontend/scripts/test-live.py` (в Windows — `.\.venv\Scripts\python.exe`). Проверка сама создаёт временную синтетическую базу, запускает реальный HTTP-сервер и проверяет сессии, права, CSRF, завершения, повторы, конфликт версии, импорт и сохранение после перезапуска. Рабочую базу она не использует.

На объединённой версии 2026-09-23 прошли **67 frontend-теста**, TypeScript и production-сборка. Включены проверки периода и знаменателей HR, поздних ответов, публичного входа и переключения ролей, ошибок и сохранённого частного входа. На сервере прошли **488 тестов**, включая 10 проверок публичного режима и 10 HR. Подробности, история прогонов и границы — [VERIFICATION](VERIFICATION.md).

На этой машине нет ключа для нового live AI-прогона: полный путь через фактический ответ модели здесь ещё не подтверждён. Отчёты Олега в каталоге AI относятся к его окружению. Также не подтверждены новый Docker-образ, постоянный публичный HTTPS-адрес, production-настройки и SLA. После настройки модели и размещения нужно повторить сценарий с новыми проверочными профилями, замерить задержки и записать фактические результаты на опубликованном коммите.
