## Какие данные и ответы используются

**Рабочий вход** отправляет запросы настоящему backend. `pnpm start:demo` лишь создаёт отдельные вымышленные входные данные в SQLite: навыки, доступность, прогресс, история и импорт затем обрабатываются настоящим серверным кодом. Этот запуск намеренно выключает AI.

**Кнопка «Посмотреть демо»** включает готовые ответы в браузере. Она нужна для осмотра интерфейса и проверки его состояний, а не для доказательства основного AI-сценария. Режим постоянно подписан, пользовательские файлы не принимает. Отказ API не переключает приложение на эти ответы.

Исходный набор кейса загружается локально по [HANDOFF](../docs/HANDOFF.md). Реальные профили, исходный ZIP, пароли, токены и БД в репозиторий не включены.

## Проверить настоящую запись результата

1. Установить зависимости и запустить `pnpm start:demo` по [инструкции](README.md#приложение-с-настоящим-api-на-синтетических-данных).
2. Открыть `http://127.0.0.1:5173` и войти обычной формой под сотрудником. Учётные данные созданы локально в `.local-demo.json`; общих паролей в Git нет.
3. Открыть «Каталог активностей», выбрать доступный курс и посмотреть предварительные изменения навыка. Пока завершение не подтверждено, профиль не меняется.
4. Подтвердить завершение. Проверить сравнение до/после и запись в истории. Обновить страницу: результат должен сохраниться. Повтор той же команды не должен начислить рост дважды.
5. Выйти и войти как HR. Загрузить профиль и историю в формате [API v1](../contracts/API.md): сначала проверить, затем подтвердить. Новые записи должны появиться в списке; некорректные файлы должны быть отклонены без частичной записи.
6. Запросить рекомендации. На этой основе при выключенном AI ожидается честное сообщение о неподключённом подборе. Это фиксирует оставшийся пробел, а не прохождение полного AI-сценария.

Автоматическая проверка соответствующих серверных операций: из корня `.venv/bin/python frontend/scripts/test-live.py`; в Windows — `.\.venv\Scripts\python.exe frontend/scripts/test-live.py`. Она использует временную БД и не меняет рабочие данные.

## Приоритет перед сдачей в пределах пяти часов

Сначала интегратор объединяет готовые изменения `codex/ai-recommendations` и `codex/backend-ai-handoff` после командного review, подключает AI локальными переменными окружения и проверяет полный путь **новый профиль → настоящая рекомендация с основаниями → завершение → новый прогресс**. Дополнение серверных facts подготовлено в backend-handoff ветке; наличие отдельной ветки не означает, что оно уже работает в текущем приложении.

Затем проверяются импорт жюри, восстановление после перезапуска и запуск итогового коммита в отдельном окружении. Только фактически пройденные проверки переносятся в README. Остальное время — на дефекты и короткую демонстрацию; дополнительные декоративные функции не являются приоритетом. Утверждение, что вся разработка уложилась ровно в пять часов, не делается: такого замера у этой записи нет.

## Визуальная система

Интерфейс использует зелёное направление [официального сайта Halyk](https://halykbank.kz/ru), тёплую светлую основу и золотистые акценты. Казахские надписи — часть оформления, полноценная локализация не заявляется. Орнамент и знак Career Quest созданы в SVG по мотивам зеркальных роговых форм; это собственные векторные элементы, а не копия официального логотипа банка. Они локальные, не зависят от генерации изображений и скрыты от скринридера. Основной текст и действия не перекрываются орнаментом.

Оформление помогает читать цель, объяснение и результат, но само по себе не подтверждает функциональность и не даёт дополнительных баллов по приведённой шкале.
